# Beginner-friendly plan or implementation explainer

Explain the current work to me like I am a college student with basic programming knowledge and no repo context.

Start by labeling it: PLAN, IMPLEMENTATION, or BOTH.

Use this shape:
1. Plain-English summary: enough bullets to explain what changed and why it matters.
2. Repo map: the important files/folders/components and what each one does.
3. Step-by-step: what happens in order, described as behavior.
4. Why this way: the main reason for the approach, plus one tradeoff if relevant.
5. What to remember: the key takeaways, with no forced bullet limit.

Rules:
- Define unfamiliar terms the first time you use them.
- No code dumps. Translate code into plain behavior.
- Use a tiny ASCII diagram only if it makes things clearer.
- Prefer short, clear sentences over complete-but-dense detail.
